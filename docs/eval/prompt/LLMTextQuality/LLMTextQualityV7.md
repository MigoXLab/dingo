# 一、完整性

## 1. 公式

### 1.1 Formula_Missing

中文标签：公式整体缺失

含义：原文中明确应该存在一个完整公式、方程或结构式，但抽取结果中整个公式都没有被保留下来。

典型情况：

- “公式如下”“可得”“矩阵为”“结构式为”后没有任何公式；
- 只留下公式编号，没有公式正文；
- 只留下 `[公式1]`、`[化学式1]`、`(I)` 等占位符，没有对应公式或结构式；
- 正文紧接着解释公式中的变量，但被解释的公式不存在；
- 一个关键公式的位置被页眉、页码或其他段落替代；
- “Writing out the components ... yields”等引导语后直接进入维度说明或普通正文，实际矩阵没有出现；
- 正文明确依赖某个方程，但该方程在当前完整样本中不存在，导致推导无法继续理解；
- 连续引用多条缺失公式，并且变量定义、计算过程或结论依赖这些公式；
- 专利权利要求反复引用核心化学式，但所有结构式都只剩编号或占位符。

不应标记：

- 只是引用外部文献中的公式；
- 文本明确说明省略推导过程；
- 当前样本只是原文的一小段，没有证据证明公式应该包含在该片段中；
- 公式编号不连续，但上下文并不依赖缺失公式；
- 文章只讨论某个定理、结果或模型，没有承诺展示具体公式；
- 只说“根据上式”“参见公式（3）”，但没有可见的抽取断裂、空占位或语法空槽；
- 公式以图片形式存在，而且当前任务并不要求把图片公式转换为文本；
- 单个编号缺失，但其前后推导仍然完整、可理解。

### 1.2 Formula_Partial_Loss

中文标签：公式部分缺失

含义：公式仍然存在，但其中一个具有实际数学或科学意义的组成部分被删除。

典型情况：

- 变量、常量或参数完全消失；
- 加号、减号、乘号、除号等运算符丢失；
- 等号、不等号、映射箭头、趋近箭头或集合关系符号丢失；
- 分式只剩分子或分母；
- 等号左侧或右侧表达式缺失；
- 函数参数或函数名缺失；
- 求和、积分、极限的上限或下限缺失；
- 分段函数缺少一个或多个分支；
- 矩阵仍在，但某些必要元素整块缺失；
- 化学式中的元素数量、下标、价态、电荷或化学键完全消失；
- 科学单位中的指数或关键单位成分消失；
- 公式被截断，只保留开头或结尾的一部分；
- `T(s,a,s') [0,1]` 中映射箭头消失；
- `x+y=` 中等号右侧表达式消失；
- 数学正文出现“where ... is”之类定义结构，但被定义的变量位置为空。

不应标记：

- 整个公式完全消失，这应标记为 `Formula_Missing`；
- 公式只是省略了推导步骤，但最终表达式完整；
- 使用数学上合法的简写形式；
- 省略了可以从惯例直接理解、且不影响表达含义的符号；
- 仅凭领域知识猜测公式“应该还有一项”；
- 公式来自截取片段，没有可见证据证明当前片段丢失了内容；
- 对应位置留下了乱码、错误字符或被拆散的字符，这应标记为 `Formula_Token_Corruption`；
- 丢失的是 `$`、花括号或环境结束符，并因此导致无法解析，这应标记为 `Formula_Unparseable`；
- 公式内容完整，只是组件被放到了错误位置，这应标记为 `Formula_Structure_Corruption`。

### 1.3 Formula_Token_Corruption

中文标签：公式字符或符号损坏

含义：公式中的字符、数字、变量名或数学符号没有整体消失，而是被错误识别、替换、拆开或粘连。

典型情况：

- 数字被错误插入空格，例如 `10^{-3}` 变成 `1 0 ^{-3}`；
- 小数点被识别成空格、问号或其他字符；
- 一个完整数字被拆成多个数字，例如 `1.18` 变成 `1 1 8`；
- 数字被错误粘连，导致数值含义改变；
- 希腊字母被识别成相似的拉丁字母；
- 拉丁字母被识别成错误的希腊字母或 LaTeX 命令，例如 `N_2` 变成 `\Nu_2`；
- 数学变量被替换成 `�`、`□` 等乱码或占位字符；
- 单位中的字母被 OCR 错认，例如 `lx` 被识别成 `1x`；
- `R^2` 被识别成 `R^{\wedge}2` 等错误记号；
- 变量名内部被插入空格，例如 `Var` 变成 `V a r`；
- 化学式中的元素字母或数字被识别成外形相近的字符；
- 上下标内容仍然存在，但被识别成错误字符；
- 数学命令被识别成另一个无关命令；
- OCR 产生重复字符、异常字符链或错误的字符组合。

不应标记：

- 合法的变量命名差异；
- 合法的希腊字母、Unicode 数学字符或数学字体；
- 公式中存在普通空格，但不影响数字、变量和运算关系的识别；
- 为了排版而在 LaTeX 命令周围加入的合法空格；
- 同一个量在文中使用了不同但均合法的表示方式；
- 字符完全消失而没有错误字符残留，这更适合 `Formula_Partial_Loss`；
- 题号、引用、页码、日期等外部内容混入公式，这应标记为 `Formula_Extra_Content`；
- 公式字符都正确，只是分子、指数或矩阵位置错误，这应标记为 `Formula_Structure_Corruption`；
- 仅凭领域知识认为某个符号不正确，但没有 OCR 或抽取损坏证据；
- 普通正文中的拼写错误，不属于公式或科学表达式。

### 1.4 Formula_Unparseable

中文标签：公式无法解析

含义：LaTeX、Markdown、HTML 或 MathML 数学标记已经损坏，导致公式边界或语法无法被标准解析器可靠识别。

典型情况：

- 单个 `$` 没有对应的闭合 `$`；
- `$$` 显示公式定界符不匹配；
- `\(` 没有对应的 `\)`；
- `\[` 没有对应的 `\]`；
- `\frac`、`\sqrt`、上下标或其他命令所需的花括号没有闭合；
- `\begin{align}`、`\begin{array}`、`\begin{cases}` 等环境没有对应的 `\end{...}`；
- `\begin` 与 `\end` 的环境名称不一致；
- `\left` 没有合法的 `\right` 与之配对；
- 公式截断在未完成的 LaTeX 命令中；
- 公式相关 HTML 标签，如 `<math>`、`<sub>`、`<sup>`，没有正确闭合；
- MathML 标签嵌套关系损坏；
- 在明确要求 Markdown 数学格式的内容中，LaTeX 命令完全失去数学定界符，导致只显示原始命令；
- 公式边界与正文混在一起，解析器无法确定公式从哪里开始或结束。

不应标记：

- 合法的半开区间，例如 `\left(a,b\right]`；
- 合法的不可见定界符，例如 `\left.` 或 `\right.`；
- 行列式、绝对值或条件概率中合法使用的竖线；
- 混合使用行内公式和显示公式，但每个定界符都完整；
- 在 `$$...$$` 中合法使用 `align` 或 `aligned`；
- `align`、矩阵或 cases 环境中的正常换行；
- 公式能够正常解析，只是数学结构或组件位置错误，这应标记为 `Formula_Structure_Corruption`；
- 公式能够解析，只是被放在错误的行或段落，这应标记为 `Formula_Layout_Corruption`；
- 纯文本数学表达式没有 LaTeX 定界符，但表达式本身清楚、完整，而且目标格式允许纯文本数学；
- 不能只通过 `$`、括号、`\left`、`\right` 的数量机械判断，必须结合货币符号、转义字符和合法语法。

### 1.5 Formula_Structure_Corruption

中文标签：公式内部结构损坏

含义：公式可以被解析或渲染，但分式、指数、上下标、矩阵、分支、运算符作用范围等内部组合关系在抽取过程中被破坏。

典型情况：

- 本应相乘的表达式被错误放入指数；
- 指数、下标或上下标绑定到了错误对象；
- 分子和分母位置颠倒或错误组合；
- 分式被错误转换成普通数组或多行文本；
- 求和、积分或极限的上下限颠倒、错位；
- 运算符的作用范围错误；
- 括号虽然可以渲染，但表达式分组关系明显错误；
- 矩阵行列关系丢失；
- 矩阵列分隔符缺失，导致多个元素被合并到同一列；
- cases 或分段函数的分支被错误嵌套；
- 分段函数被错误转换成 `\binom` 等其他结构；
- 行列式被错误转换成非方阵或普通数组；
- 公式内部片段顺序颠倒；
- 方程左侧、右侧或运算项被放到错误层级；
- 竖式计算中的数位、运算符和结果列关系损坏；
- 公式可以显示，但显示结果所表达的内部结构与同段定义明显矛盾。

不应标记：

- 单纯的数学事实错误，例如结构完整的 `2+2=5`；
- 只是使用了不常见但合法的公式写法；
- 公式与常见教科书写法不同，但上下文内部一致；
- 仅凭领域知识推测作者公式写错，没有抽取损坏证据；
- 单个字符、数字或变量被识别错误，这应标记为 `Formula_Token_Corruption`；
- 公式中的变量、运算符或完整子表达式消失，这应标记为 `Formula_Partial_Loss`；
- 公式已经无法被解析器处理，这应标记为 `Formula_Unparseable`；
- 公式内部完整，只是与正文的换行、位置或块级显示关系错误，这应标记为 `Formula_Layout_Corruption`；
- 合法的矩阵、cases、align、分式、嵌套上下标或多行公式结构；
- 没有同文定义、完整版本、版面痕迹或其他证据可以证明组件被放错位置。

### 1.6 Formula_Layout_Corruption

中文标签：公式显示布局损坏

含义：公式内容和内部结构基本完整且能够解析，但公式与正文之间的换行、位置、行内或块级显示关系被破坏。

典型情况：

- 行内公式前后被错误插入换行；
- 一个行内公式被错误变成独立段落；
- 多个行内公式被逐个拆到单独的行中，导致句子断裂；
- 一个连续公式被错误拆成多个公式块；
- 上一个公式块以 `+`、`-`、`=` 等未完成符号结束，下一个公式块才继续表达式；
- 显示公式被错误压入普通正文；
- 公式编号与公式主体分离；
- 公式被移动到错误段落；
- 公式与其解释文字顺序错乱；
- 同一个方程因为分页被拆成上下两块；
- 行内公式与前后正文之间的换行导致语义流断裂；
- 公式主体与单位、条件或变量说明被错误分到不同段落；
- 公式本身正确，但 Markdown 的行内或块级形式转换错误，造成显示异常。

不应标记：

- 原本就应该独立显示的块级公式；
- 不影响渲染和阅读的普通换行；
- 长公式为了阅读而进行的合法换行；
- `align`、`aligned`、`cases`、矩阵环境中的正常多行排版；
- 行内公式因页面宽度自动换行，但原始 Markdown 没有插入结构性换行；
- 公式单独成行，但没有破坏句子、语义或显示效果；
- 公式内部的分式、指数、矩阵或分支关系错误，这应标记为 `Formula_Structure_Corruption`；
- 换行直接破坏了 `$` 或其他数学定界符，导致无法解析，这应标记为 `Formula_Unparseable`；
- 换行位置插入了页眉、页码、脚注或其他文字，这应标记为 `Formula_Extra_Content`；
- 仅仅是个人偏好的排版风格差异。

### 1.7 Formula_Extra_Content

中文标签：公式混入多余内容

含义：不属于公式的文字、页码、引用、题号、标记或其他内容被错误插入公式内部，或者紧贴公式形成错误表达。

典型情况：

- 公式后残留独立的 `latex`；
- 每个显示公式后都重复出现抽取器生成的 `latex` 标记；
- 页眉进入公式；
- 页脚进入公式；
- 论文标题、期刊名称或作者信息进入公式；
- 页码进入公式；
- 引用编号进入指数；
- 引用编号进入下标；
- 引用编号与单位指数粘连，例如 `[42]` 被拼进 `cm^{-1}` 形成 `cm^{-142}`；
- 题目编号被拼接成公式结果，例如下一题编号 `1` 被抽成 `145×12=1`；
- 日期被插入公式或推导过程；
- 脚注文字进入公式；
- 脚注编号被错误绑定到公式变量、指数或结果；
- OCR 将公式前后的正文拼入公式；
- 一个公式的位置被无关段落、实验步骤或另一道题的内容占据；
- HTML 标签或抽取器内部标记泄漏到公式内容；
- 图片说明、表格标题或页面导航被插入公式；
- 公式中出现与上下文无关的长字符链、重复片段或版面残留。

不应标记：

- 正常的公式编号，例如 `\tag{3}`；
- 公式闭合后正常出现的引用 `[42]`；
- 引用没有进入公式定界符、指数、下标或表达式内部；
- 公式结束后正常出现解释文字；
- 文档本身在讨论 LaTeX，因此正常出现单词 `latex`；
- 公式内部合法使用 `\text{otherwise}`、`\text{if}` 等条件说明；
- 公式中的合法单位、变量说明或文本运算符；
- 化学式、物理单位或统计符号本身包含文字；
- 正常的脚注标记位于公式外部，并且不会被理解为公式的一部分；
- 只有换行或公式位置错误，没有插入其他内容，这应标记为 `Formula_Layout_Corruption`；
- 公式自身的字符被 OCR 识别错误，这应标记为 `Formula_Token_Corruption`；
- 多余内容只是网页或文档中的普通正文，没有进入或紧贴公式形成错误表达。

## 2. 表格

### 2.1 Table_Missing

中文标签：表格整体缺失

含义：原文中明确应该存在一张表格，但抽取结果中整张表格或全部有效表体都没有被保留下来，只剩标题、表号、引导语、表头、单位、图例、注释或来源等外围信息。

典型情况：

- “如下表所示”“具体参数如下”“统计结果见下表”等引导语后没有任何表格内容；
- 只留下“表1”“Table 2”“附表九”等表号或标题，没有表头和数据行；
- 只留下表题、资料来源和脚注，表格主体完全消失；
- 只留下金额单位、百分比单位、箭头图例或颜色图例，没有对应数据；
- 只留下 `<table>` 和一行表头，所有正文数据行均不存在；
- 表格标题后直接出现下一张表的标题，当前表没有任何内容；
- 正文明确依赖表中的数值、排名、参数、评分标准或案件明细，但当前样本中完全没有这些数据；
- “换油周期参考如下表：”之类句子位于样本中间，冒号后直接结束或进入下一节；
- 多张连续编号的表中，部分表只有标题，前后表格内容正常存在；
- 表格位置只留下图片占位说明，但当前任务明确要求保留可学习的文本表格结构。

不应标记：

- 表格仍保留了一部分有效数据，这应标记为 `Table_Partial_Loss`；
- 表格内容都在，只是被拆成多个块或扁平化为文本，这应标记为 `Table_Layout_Corruption`；
- 正文只是引用外部文献、附录或其他页面中的表格；
- 当前样本明显只是文档片段，没有证据表明被引用的表格应该包含在该片段中；
- 文本只说“结果见表1”，但没有空占位、断裂引导语或其他抽取缺失证据；
- 表格编号不连续，但正文不依赖缺号表格；
- 作者明确说明表格省略、数据不可得或不适用；
- 表格以完整图片形式保留，而且当前任务允许图片表格，不要求转换为文本；
- 普通标题、目录项或图题看起来像表名，但并没有证据表明此处应有表格。

### 2.2 Table_Unparseable

中文标签：表格无法解析

含义：HTML、Markdown 或其他表格标记的语法边界已经损坏，导致标准解析器无法稳定识别表格、行或单元格。

典型情况：

- `<table>` 没有对应的 `</table>`，导致后续正文被持续包含在表格中；
- `<tr>`、`<td>` 或 `<th>` 标签缺少开始标签或结束标签；
- `<table>`、`<tr>`、`<td>`、`<th>` 的嵌套顺序错误；
- 单元格直接出现在 `<tr>` 之外，或者数据行直接出现在 `<table>` 之外；
- HTML 标签被截断，例如 `<td colsp`、`</tr` 或不完整的属性引号；
- `rowspan`、`colspan` 属性自身语法损坏，使解析器无法确定标签边界；
- Markdown 表格缺少必要的表头分隔行，因而被解析成普通文本；
- Markdown 表格的管道符严重缺失、错位或被错误转义，无法确定行和单元格边界；
- 单元格中的未转义管道符破坏整行列数，使 Markdown 解析结果不稳定；
- HTML 表格开始标记和 Markdown 表格片段被错误拼接，无法形成任何一种合法表格；
- 表格在未完成的 HTML 实体、标签或 Markdown 行中被截断，后续内容无法继续解析。

不应标记：

- HTML 标签完整且能够解析，但行列或表头对应关系错误，这应标记为 `Table_Structure_Corruption`；
- HTML 能够解析，但一张表被拆成多个独立表格块，这应标记为 `Table_Layout_Corruption`；
- Markdown 表格没有首尾管道符，但解析器仍能正确识别全部行列；
- HTML 省略了浏览器允许省略的标签，而且最终表格可以稳定解析；
- 单元格数量不同是合法的 `rowspan` 或 `colspan` 造成的；
- 表格语法正确，只是部分数据单元格为空，这应根据证据考虑 `Table_Partial_Loss`；
- 表格语法正确，只是某个单元格内部出现乱码，这应标记为 `Table_Cell_Corruption`；
- 纯文本使用空格、制表符或对齐字符表达表格，并且字段关系仍然清楚；
- 仅通过开始标签和结束标签的数量机械判断，必须同时确认标签顺序、上下文和实际解析结果。

### 2.3 Table_Partial_Loss

中文标签：表格局部缺失

含义：表格仍保留了可识别的表头或部分有效数据，但一个或多个有实际意义的行、列、单元格或连续内容在抽取过程中丢失。

典型情况：

- 表格中间缺少一段连续编号的行，例如第26项之后直接跳到第44项；
- 某个必要数据列整列为空，而其他列数据正常存在；
- 一行只剩行名，所有数值、状态或说明均缺失；
- 多行都缺少 Total、合计、结果、评分或关键测量值；
- 同类记录通常包含候选人、商品名或项目名，但某一行只剩类别标题；
- 表头列出了多个时间段，数据行却系统性缺少最后一个时间段；
- 表格只保留前半部分，后续行或后续列被截断；
- 单元格在半句话、半个单词或未完成的数值处结束，而且没有后续内容；
- 矩阵表、相关系数表或统计表只剩部分三角区域，原本必须存在的区域为空；
- 表格中原应出现的交互项、模型参数、指标或分类列完全缺失；
- 表格主体仍有数据，但一个子表、一个分组或一个连续年份的数据全部消失；
- 若干必要单元格被空白占位替代，使对应记录无法完整恢复。

不应标记：

- 整张表或全部表体都不存在，这应标记为 `Table_Missing`；
- 单元格内容仍在，但被识别成错误字符、乱码或占位词，这应标记为 `Table_Cell_Corruption`；
- 两列内容被合并到一个单元格，或数值被放进错误列，这应标记为 `Table_Structure_Corruption`；
- 表头本身缺失或损坏，并且表体数据仍完整，这应标记为 `Table_Header_Corruption`；
- 合法的空单元格、跨行合并单元格或跨列合并单元格；
- `N/A`、`NaN`、`-`、空白等是原表明确表达的“不适用”“未披露”或“无数据”；
- 汇总表只展示作者有意选择的部分指标；
- 因当前样本截取范围有限而看不到后续行，但没有抽取中断证据；
- 仅凭领域知识猜测表格“应该还有一列”或“应该还有更多记录”。

### 2.4 Table_Cell_Corruption

中文标签：单元格内容损坏

含义：单元格的位置及其所属行列基本明确，但单元格内部的文字、数字、符号或代码被错误识别、替换、重复、拆开、粘连或截断。

典型情况：

- 实体名称、商品名称、机构名称或人名被截去开头或结尾；
- `D445`、`D92` 等标准编号中的字母被错误删除；
- `否` 被识别成 `香`，或其他 OCR 形近字替换改变单元格含义；
- IPA、数学符号、货币符号、百分号、正负号或单位字符被识别成错误字符；
- 一个数值内部的小数点、分隔符、指数或单位被损坏；
- 单词内部被错误插入空格，例如表头或字段值被拆成多个字符片段；
- 单元格出现长串重复汉字、字母、数字或符号，例如 `沢沢沢...`；
- 正常内容被 `manipulation`、乱码、占位字符或无意义字符链替代；
- 日期、编号或代码被 OCR 错认，但仍明确属于当前单元格；
- 一个单元格内本应有分隔符的内容被错误粘连，但没有改变相邻列的数量和对应关系；
- 单元格文本在词语中间截断，而行列结构仍然完整；
- 同一表中存在完整写法，可直接证明另一个单元格发生了字符级损坏。

不应标记：

- 整个单元格、整行或整列完全丢失，这应标记为 `Table_Partial_Loss`；
- 两个相邻列的值被合并进一个单元格，导致列对应关系改变，这应标记为 `Table_Structure_Corruption`；
- 损坏的是表头字段，应优先标记为 `Table_Header_Corruption`；
- S3 地址、页眉、正文或其他外部内容进入单元格，这应标记为 `Table_Extra_Content`；
- 仅凭领域知识认为某个名称、数字或结论错误，但没有可见的 OCR 或抽取损坏证据；
- 原文自身使用缩写、特殊代码、罕见字符或行业术语；
- 合法的多值单元格、枚举内容、换行或分号分隔内容；
- 普通正文中的乱码或粘连，没有发生在表格单元格中；
- 一个可读数值只是与其他数值逻辑矛盾，但看不出字符或抽取结构损坏；这种情况不使用表格质量标签推断事实错误。

### 2.5 Table_Header_Corruption

中文标签：表头损坏

含义：表格主体仍然存在，但列名、分组表头、子表头、行标题体系或表头跨行跨列关系发生缺失、错误、重复、截断或粘连，导致列语义不完整或错误。

典型情况：

- 表体存在一个稳定的数据列，但对应列名完全缺失；
- 表头缺少“容积率”等必要字段，导致后续数据看起来整体错位；
- 两个不同年份的列被错误标成同一个年份；
- `Pseudo-first-order model` 被重复用于两个不同模型分组；
- 城市名称列被错误标为“所在行业”，或经验年限列沿用了其他表格的表头；
- 表头文字被截断，例如只剩 `Re`、`SOUTH' D.` 或半个字段名；
- 多个列名被压进同一个表头单元格，例如“授出 行使 注销 失效”；
- 一个分组表头声明跨7列，但其下实际存在8个子表头；
- 表头缺少必要的上级分组或下级子列，无法确定数据列含义；
- 表头顺序被颠倒、重复插入，或在表体中间异常再次出现；
- 表头与紧邻脚注、单位或表内定义明确矛盾；
- 表头中的时间、单位、模型名或分类名被错误替换，导致整列语义发生变化。

不应标记：

- 表头正确，但数据行整体向左或向右错位，这应标记为 `Table_Structure_Corruption`；
- 表头与表体被拆成两个独立块，这应标记为 `Table_Layout_Corruption`；
- 表题或表号与后面的表体错配，这属于表格上下文布局问题，应标记为 `Table_Layout_Corruption`；
- 只有表头而完全没有表体，这应标记为 `Table_Missing`；
- 表头中的一个字符发生普通 OCR 损坏，但不影响列含义；只有达到实质影响时才标记；
- 合法的多级表头、斜线表头、跨行表头或跨列表头；
- 简单键值表、两列表或列表型表格本来就不需要显式表头；
- 同一列名在分页续表中正常重复；
- 表头使用缩写、代码或专业术语，但表内或上下文能够明确理解。

### 2.6 Table_Structure_Corruption

中文标签：表格结构损坏

含义：表格语法可以解析，主要内容也仍然存在，但行、列、单元格、表头和数据之间的网格关系在抽取过程中被破坏，导致字段和值无法可靠对应。

典型情况：

- 表头有5列，数据行却稳定出现7个单元格，导致后续数值整体错位；
- 某行数值向左或向右移动，被放入错误的数据列；
- 行标签向上或向下错位，与相邻行的数据错误配对；
- 两个相邻列的数值被合并为一个单元格，另一列因此为空；
- 一个逻辑记录被拆成多行，后续记录继承了错误的值或标签；
- 多条记录被压进同一行或同一单元格，无法再恢复记录边界；
- `rowspan` 或 `colspan` 数值错误，使合并单元格覆盖了不应覆盖的行列；
- 分组表头与实际子列数量不一致，使数据无法对应到正确分组；
- 行标签“组间”“总和”等被拼进变量名称，原有层级关系消失；
- 合计、年份、价格、百分比或状态值被放到错误表头下面；
- 表格中的类别层级错误，例如同级类别被抽成上下级关系；
- 同一行的多个字段被压成一串没有可靠边界的文本和数值；
- 表格可以渲染，但行列关系已经无法从渲染结果中可靠恢复；
- 表头、表体和合计行各自可读，但三者的列边界彼此不一致。

不应标记：

- HTML 或 Markdown 语法已经损坏到无法解析，这应标记为 `Table_Unparseable`；
- 一个单元格的位置明确，只是其内部字符被 OCR 错认，这应标记为 `Table_Cell_Corruption`；
- 一个必要行、列或单元格完全消失，这应标记为 `Table_Partial_Loss`；
- 一张表被拆成多个表格块，块内行列仍然正常，这应标记为 `Table_Layout_Corruption`；
- 表头字段自身错误，但表体网格关系正常，这应标记为 `Table_Header_Corruption`；
- 合法使用 `rowspan`、`colspan`、多级表头、空白占位单元格或合计行；
- 不同数据行因为合法合并单元格而拥有不同数量的 `<td>`；
- 扁平化后的纯文本仍能通过稳定分隔符恢复每行字段关系；
- 表内数值看起来不合理，但没有字段错位、合并、拆分或其他抽取损坏证据；
- 仅仅因为表格设计复杂、列数较多或视觉样式不美观。

### 2.7 Table_Layout_Corruption

中文标签：表格布局损坏

含义：表格的主要内容可能仍然存在，各局部块也可能可以解析，但表头、表体、数据行、表题或章节之间的块级位置、顺序和归属关系被破坏。

典型情况：

- 一张连续表格被错误拆成两个或多个互不连接的 `<table>`；
- 表头单独形成一个表格，数据行又形成另一个没有表头的表格；
- 部分数据行掉到 `</table>` 之外，变成普通正文；
- 表格被扁平化成多段列表，行名和值分别集中在不同位置，无法重新配对；
- 多列表格被压成线性文本，记录边界和列边界同时丢失；
- 分页后续表没有继承表头，并与前一页表体断开；
- 一个表格的标题后出现了另一张表的数据，正确表体被放到后面的错误标题下；
- 表1标题后直接出现表2标题，而表1的数据实际位于表2标题下面；
- 某章节下出现另一章节的数据表，原章节对应表格被移到别处；
- 表格续页、附表或子表顺序错乱，导致表题和表体关联错误；
- 同一逻辑记录跨两个表格块断开，前半部分和后半部分无法可靠拼接；
- 多栏页面抽取后，不同表格或不同栏目的内容交叉排列。

不应标记：

- 一张表内部的行列错位、合并或跨度错误，这应标记为 `Table_Structure_Corruption`；
- 表格标题存在，但整个表体完全消失，这应标记为 `Table_Missing`；
- 外部正文、图片地址、页眉或无关内容被插进表格内部，这应标记为 `Table_Extra_Content`；
- 多张表本来就是相互独立的表格块；
- 正常分页续表，并且表号、续表标识、表头和数据关系清楚；
- 为适应页面宽度，将宽表拆成左右两个块，但可以明确、无歧义地重新对应；
- 表格前后存在正常的标题、注释、图例、来源或解释段落；
- 纯文本表格虽然没有 HTML 标签，但每行字段仍可稳定恢复；
- 表格只是位置不美观、居中方式不同或视觉间距异常，但数据归属关系没有受到影响。

### 2.8 Table_Extra_Content

中文标签：表格混入多余内容

含义：不属于当前表格的正文、图片地址、页眉页脚、章节内容、系统标记或其他数据被错误插入表格内部或单元格中，污染了表格内容。

典型情况：

- 单元格中出现原始 S3 图片地址、抽取路径或内部存储链接；
- 本应是日期、数值或说明的单元格被 `<img src="s3://...">` 占据；
- 正文分析段落被完整嵌入表格行或单元格；
- “Result of ...”“From table ...”等章节标题和后续讨论被塞进表体；
- 页眉、页脚、页码、文档标题、作者信息或版权声明进入数据行；
- 网页导航、按钮、筛选项、UI 提示或广告文本进入单元格；
- 抽取器生成的占位词、HTML 残留标记或内部注释进入表格；
- 脚注、引用编号或来源文本被拼进数值，形成错误的数据内容；
- 一张完全无关的表格被插入当前表格的记录序列中；
- 另一个章节的正文或数据混入当前表格，使表格主题突然改变；
- 图注、公式说明或图片识别文本被当作表格数据行；
- 原有单元格内容仍在，但前后又粘连了不属于该字段的外部文本；
- 页面重复内容或版面残留被批量插入多个单元格。

不应标记：

- 表格正常包含脚注、引用、来源、单位、备注或说明列；
- 单元格中的链接、图片、公式或换行本来就是表格的有效内容；
- 外部内容位于表格之前或之后，没有进入表格边界，也没有与单元格粘连；
- 表格被整体放到错误章节或错误表题下面，但内容没有插进表格内部，这应标记为 `Table_Layout_Corruption`；
- 单元格自身被 OCR 识别成乱码或重复字符，没有明确的外部内容来源，这应标记为 `Table_Cell_Corruption`；
- 表格中某个必要值被图片占位符完全替代时，可根据主要问题选择 `Table_Extra_Content`；不要再用多个标签重复描述同一处损坏；
- 表格合法包含多段文本、项目列表、定义、说明或备注；
- 表格中的空白、`N/A`、破折号或零值；
- 仅仅因为表格内容与文章主题不同，但没有明确的错页、错栏或抽取混入证据。

## 3. 代码

### 3.1 Code_Missing

中文标签：代码整体缺失

含义：原文中明确应该存在一段完整代码、配置、脚本或程序清单，但抽取结果中整段代码都没有被保留下来。

典型情况：

- “代码如下”“示例程序如下”“实现见下方代码”等引导语后没有任何代码；
- 只留下“程序清单5-3”“Listing 2”“示例代码”等标题，没有代码正文；
- 只留下 `python`、`java`、`matlab`、`json` 等语言标识，没有对应代码块；
- 只留下代码运行结果、输出截图说明或变量解释，被解释的代码不存在；
- 正文逐项说明某个函数、类或接口中的变量和流程，但对应实现完全缺失；
- 代码位置只剩空围栏、空白 `<div>`、图片占位符或抽取器占位文本；
- 连续编号的多个程序清单中，某个清单只有标题，前后清单均包含正常代码；
- 教程要求读者复制、修改或运行下方程序，但下方直接进入下一节；
- 题目要求分析一段给定程序的输出，但被分析的程序完全没有出现；
- 文档当前部分明确依赖缺失代码，导致接口、参数或执行流程无法理解。

不应标记：

- 代码仍保留了一部分，只是后半段缺失，这应标记为 `Code_Partial_Loss`；
- 代码内容仍在，只是围栏、换行、缩进或代码块位置损坏，这应标记为 `Code_Layout_Corruption`；
- 只是引用外部仓库、附件、附录或其他章节中的代码；
- 当前样本明显只是文档片段，没有证据证明代码应该出现在该片段中；
- 作者明确说明省略实现、只给伪代码、只展示接口或让读者自行完成；
- 文本只是讨论某种语言、算法或 API，没有承诺展示代码；
- 代码以图片形式完整保留，并且当前任务允许图片代码，不要求转换为文本；
- 一条短命令、函数名或内联表达式没有代码围栏，但本身清楚可读；
- 程序清单编号不连续，但上下文并不依赖缺号代码。

### 3.2 Code_Unparseable

中文标签：代码无法解析

含义：代码、JSON、XML、配置或脚本的结构性语法边界已经损坏，导致对应语言的标准解析器无法可靠建立字符串、表达式、语句或块结构。

典型情况：

- 字符串的单引号、双引号或三引号没有闭合；
- 圆括号、方括号、花括号或其他成对定界符缺少一侧或嵌套顺序错误；
- C、C++、Java、JavaScript 等代码块的 `{` 与 `}` 无法配对；
- Python 函数、条件或循环头部缺少必要的冒号，导致语句块无法解析；
- JSON 中出现 `\u00b` 等非法 Unicode 转义，或者字符串、逗号、冒号结构损坏；
- XML 声明、开始标签、结束标签或属性引号损坏，例如 `<?xml version=.0" encoding=TF-8"?>`；
- PHP、Shell、正则表达式或其他语言的引号、转义或命令边界没有闭合；
- 代码在未完成的字符串、表达式、函数调用或标签中结束；
- 同一个代码块中混入互不兼容的语法标记，无法确定应按哪种语言解析；
- 预处理指令、配置项或序列化结构被破坏到无法识别其完整语法边界；
- 一个局部字符问题造成多行语句都无法确定起止位置，解析器无法继续恢复后续结构。

不应标记：

- 某个标识符、关键字或运算符被清楚地识别成错误词元，这应优先标记为 `Code_Token_Corruption`；
- 函数或程序后半部分整体消失，这应标记为 `Code_Partial_Loss`；
- 代码可以解析，只是换行、缩进、围栏或代码与正文的布局错误，这应标记为 `Code_Layout_Corruption`；
- 代码能够解析，但存在逻辑错误、运行时异常、类型错误、未定义变量、缺少依赖或错误 API 调用；
- 教学材料有意展示错误代码、反例、异常信息或需要读者修复的程序；
- 伪代码、BNF、正则表达式、命令行片段或配置片段使用了与通用编程语言不同的合法语法；
- 当前内容只是一个有意截取的表达式、函数片段或 diff，不要求独立编译；
- 仅通过括号或引号数量机械判断，必须结合注释、字符串、转义和具体语言语法；
- 代码缺少 Markdown 围栏，但代码本身的边界和语法仍然清楚。

### 3.3 Code_Partial_Loss

中文标签：代码部分缺失

含义：一段可识别的代码仍然存在，但函数、类、语句、声明、分支、循环、返回逻辑或程序尾部等具有实际作用的组成部分在抽取过程中丢失。

典型情况：

- 函数只剩前半部分，在循环或条件块中突然结束；
- MATLAB 程序在嵌套 `while` 或 `for` 中直接进入参考文献，后续 `end` 和计算逻辑全部消失；
- C 代码块从若干局部语句开始，函数签名、参数和必要声明不见了；
- 一个完整示例应包含初始化、处理和返回步骤，但只保留其中一部分；
- 代码在赋值号、运算符、函数调用或未完成的语句中截断；
- 某个分支只有 `if`，对应的主体或后续 `else` 内容明显缺失；
- 函数主体存在，但必要的返回语句和结束部分完全消失；
- 类定义存在，但关键方法、字段分组或类结尾被截断；
- 配置或 JSON 数组只保留前几个项目，后续部分在页面或章节切换处消失；
- 题目中的程序尚未闭合，下一道题直接插入，显示原代码尾部没有被保留；
- 代码注释明确描述后续步骤，但对应实现没有出现；
- 同一代码在文中另有完整版本，可明确确认当前代码丢失了一段连续内容。

不应标记：

- 整段代码完全没有出现，这应标记为 `Code_Missing`；
- 只有一个引号、括号、花括号或标签缺失，并且主要问题是无法解析，这应标记为 `Code_Unparseable`；
- 对应位置残留了错误标识符、乱码或错误运算符，这应标记为 `Code_Token_Corruption`；
- 代码内容完整，只是换行、缩进或块位置错误，这应标记为 `Code_Layout_Corruption`；
- 教学示例明确使用 `...`、`pass`、`TODO` 或注释表示有意省略实现；
- 当前样本明确只展示函数片段、调用片段、补丁片段或核心算法；
- 示例代码不包含完整工程、依赖文件、测试或异常处理；
- 仅仅因为代码不能独立运行，就猜测存在内容丢失；
- 未声明变量或缺少导入可能是原代码问题，不能在没有抽取证据时推断为缺失。

### 3.4 Code_Token_Corruption

中文标签：代码字符或词法单元损坏

含义：代码中的关键字、标识符、运算符、数字、字符串字符、路径、转义符或其他词法单元没有整体消失，而是被错误识别、替换、拆开、粘连或重复。

典型情况：

- C 语言关键字 `int` 被 OCR 识别成 `at`；
- 运算符 `-=` 被识别成 `μ=`，或者 `=` 被识别成无关符号；
- MATLAB 的 `[~, EEG]` 被识别成 `[-, EEG]`；
- `LayoutInflater` 等标识符中混入中文、乱码或其他无关字符；
- JavaScript 选择器、字符串或属性名中的引号、点号、括号字符被错误替换；
- PHP 变量 `$db`、`$_SESSION` 前被系统性插入多余反斜杠；
- AutoLISP 的 `(setq ss ...)` 被粘连成 `(setqss ...)`，函数名和参数边界消失；
- 标识符内部被错误插入空格、连字符或换行，形成新的无效词元；
- 文件名、路径、宏名或代码常量中的字符被 OCR 错认；
- 数字、小数点、十六进制前缀、指数、位运算符或数组下标被破坏；
- 代码中出现长串 `UUUU...`、`1.1.1.1...` 或其他重复垃圾字符；
- 有效命令被识别成外形相似但不存在的命令，例如 `esurf` 变成 `osuuf`；
- 同一变量或函数在相邻位置存在正确写法，可直接证明另一个词元被破坏；
- Markdown 或 OCR 转义改变了代码的实际字符，而不是只改变显示样式。

不应标记：

- 整个函数、语句、分支或程序尾部消失，这应标记为 `Code_Partial_Loss`；
- 引号、括号、转义或标签结构整体损坏，主要问题是无法解析，这应标记为 `Code_Unparseable`；
- 多条语句因为换行丢失而粘在同一行，这应标记为 `Code_Layout_Corruption`；
- 行号、IDE 提示、题目文字、LaTeX 标记或页眉混入代码，这应标记为 `Code_Extra_Content`；
- 变量名、函数名、缩写或编码风格不符合个人习惯，但在当前语言中合法；
- 代码使用 Unicode 标识符、非英文注释、特殊运算符或领域专用语法，并且用法合法；
- 代码存在逻辑错误、拼写式命名、过时 API、错误算法或低效实现，但没有 OCR 或抽取损坏证据；
- 仅凭外部知识认为某个标识符“应该是另一个名字”；
- Markdown 为显示 `$`、反斜杠或反引号进行合法转义，而且渲染后的代码字符正确；
- 普通正文中的乱码或字符粘连，没有发生在代码、配置或脚本中。

### 3.5 Code_Layout_Corruption

中文标签：代码布局损坏

含义：代码的主要词元和语句仍然存在，但换行、缩进、代码围栏、注释边界、代码块顺序或代码与正文之间的位置关系在抽取过程中被破坏。

典型情况：

- 多条 C、C++、Java 或 C# 语句被压到同一行；
- 换行丢失后，`//` 注释吞掉后续变量声明或可执行语句；
- `#define` 与宏值被错误拆到不同的行，改变预处理指令含义；
- Python、YAML、Makefile 等依赖缩进的代码失去层级，无法恢复语句块；
- 一个 MATLAB 注释被强制换行，续行丢失 `%` 并被当成代码；
- 代码围栏丢失，只留下独立的语言名和散落代码，导致代码与正文边界不清；
- 一个连续程序被错误拆成多个互不连接的代码块；
- 代码块顺序颠倒，函数调用出现在被截断的定义中间；
- 正文段落被插入代码块之间，导致原本连续的语句被打断；
- 行尾续行符、反斜杠或语言特定的续行关系因换行重排而失效；
- 原本并排展示的多栏代码被逐行交叉，两个程序的语句互相穿插；
- 代码、运行结果和解释文字的块级顺序错乱，无法确定哪些行属于程序；
- 长代码行在字符串、标识符或预处理指令中间被错误硬换行；
- 行内代码被逐词拆成多行，导致表达式边界无法恢复。

不应标记：

- 缺少 Markdown 代码围栏，但缩进、代码边界和语法仍然清楚；
- 代码使用 `<pre>`、`<code>`、`<div class="mineru-algorithm">` 或其他可识别容器，而不是三反引号；
- C、JavaScript 等代码采用压缩或单行风格，但语法边界完整且可解析；
- 不同的括号风格、空格数量、制表符宽度或格式化习惯；
- 长语句在语法允许的位置正常换行；
- Python、YAML 等代码保留了正确缩进，只是文档显示时视觉间距不同；
- 代码本身被截掉一大段，这应标记为 `Code_Partial_Loss`；
- 代码内部某个词元被拆开或粘连，这应标记为 `Code_Token_Corruption`；
- 外部行号、正文或系统提示被插入代码，这应标记为 `Code_Extra_Content`；
- 合法的 REPL 会话、diff、堆栈信息或带提示符的命令示例；
- 只是排版不美观，但不影响代码边界、层级和语义。

### 3.6 Code_Extra_Content

中文标签：代码混入多余内容

含义：行号、IDE 标记、题目正文、LaTeX 标记、页眉页脚、抽取器信息或其他不属于当前程序的内容被错误插入代码块或代码语句中。

典型情况：

- 函数定义前混入 IDE 的 `1 usage`、`3 references` 等提示；
- PDF 中的行号被复制到每一行 JavaScript、C 或其他代码前；
- 程序尚未结束，下一道考试题的题号和文字被插入循环或函数内部；
- MATLAB 赋值运算符周围混入 `$...$`、`\mathtt{...}`、`\equiv` 等 LaTeX 标记；
- 页眉、页脚、页码、章节标题、版权声明或文档标题进入代码块；
- 网页按钮、导航、复制提示、语法高亮标记或 IDE 操作菜单进入代码；
- 原始 S3 地址、抽取路径、图片占位符或系统内部标记被当成代码；
- 代码行中混入题目分值、选项、答案说明或普通教学正文；
- 图片说明、表格内容、公式编号或图注被插入函数主体；
- 另一个程序的无关片段被拼入当前代码块；
- 抽取器把代码语言标识、围栏残片或渲染标记插入语句内部；
- 原有代码仍然可见，但前后附着了无法属于该语句的外部文本；
- 大段页面残留内容重复进入多个代码位置，破坏正常代码结构。

不应标记：

- 合法的代码注释、文档字符串、许可证头、作者信息或使用说明；
- 正常的行号展示与代码正文有清晰分隔，不会被解析为代码词元；
- 合法的 REPL 提示符、Shell 提示符、调试输出或交互式会话记录；
- 代码示例本来就在演示 LaTeX、HTML、Markdown、正则表达式或字符串转义；
- Markdown 为正确显示代码而使用的转义，渲染后没有多余字符；
- 外部说明位于代码块之前或之后，没有进入代码边界；
- 代码自身出现错误字符或乱码，但没有明确外部内容来源，这应标记为 `Code_Token_Corruption`；
- 代码与正文只是块级顺序或边界错误，没有外部内容进入具体代码，这应标记为 `Code_Layout_Corruption`；
- 有效代码行被抽取器重复多次时，可使用已有的 `Duplication`；不要新增 `Code_Duplication`；
- 数学公式后的独立 `latex` 残留不属于代码问题，应使用 `Formula_Extra_Content`；
- 单纯因为代码无法运行，就把报错信息、注释或输出误认为多余内容。
